## Learned

- A bigger thread stack does not let the old FXC compiler build the cloud march: at 64 MiB and at
  1 GiB it overflowed at the same point. Some compile failures are not about the stack size at all.
- A background build gets slower once nothing waits for it, because everything else takes the
  cores: the cloud pair took 15.9 s at normal priority against 9 s inside the startup wait, so its
  two threads now run one step above normal.
- The boot check that CLAUDE.md names for renderer work had been running on the slow compiler
  ever since its build folder was last emptied, so its timings were the slow compiler's.
