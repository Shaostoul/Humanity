# data/media: clips that ship with the game

Video files an in-world screen can play through the purpose-built player
(`src/media`, design: `docs/design/media-player.md`). A screen names one with
`screen_source: Some("video:media/<file>.webm")` in `data/machines/home.ron`;
the path is resolved against this data directory first, then the repo root,
the same rule GLB models follow (`docs/game/model-pipeline.md`). Provider and
behaviour (looping, click to pause, sound placed at the screen):
`docs/design/in-world-screens.md`, "Video sources".

Only WebM with AV1 video and Opus audio plays. Anything else is refused by
name on the screen (the codec, and the fix: transcode to WebM AV1 + Opus).

## Files

| File | Provenance |
|---|---|
| `demo_colour_bar.webm` | A byte-identical copy of `tests/fixtures/media/colour-bar-av1-opus.webm`, generated by `scripts/make-media-fixtures.sh` from SYNTHETIC ffmpeg lavfi sources: nothing recorded, nothing downloaded, so it carries no third-party rights. 2 s, 320 x 180, 30 fps, AV1 (libaom) plus stereo Opus; a 40 px red bar slides right at 140 px/s over a dark grey field and the audio is a 440 Hz tone. 19,629 bytes. |

To regenerate: run the script (needs an ffmpeg with libaom and libopus), then
copy the fixture here under the same name. The media tests in
`src/media/tests.rs` check the fixture's pixels and samples; the screen tests
in `src/engine/screens/video.rs` open THIS copy, so the two must stay
identical.
