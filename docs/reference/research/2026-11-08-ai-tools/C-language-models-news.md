# AI scan, group C: open-weight language models and news

Source video: "AI finally sleeps, Gemini 4 Carbon, ETH cracked, energy-based models, Anthropic IPO: AI NEWS"
(AI Search, 2026-10-31). Everything below was read on **2026-11-08** from the primary sources named,
by an automated research agent identifying itself honestly. Nothing was downloaded or installed;
model metadata came from each Hugging Face model page and the public Hugging Face model API
(`huggingface.co/api/models/<id>`), and repository facts from the GitHub API. Release dates are the
Hugging Face repository creation dates unless a page states its own.

**Two refusals, not worked around:** openai.com answered HTTP 403 to automated reading (the post and
openai.com/science); sec.gov refused the declared research-tool User-Agent and asks for
"company specific information", which the brief rules out, so the S-1 itself was skipped and
Anthropic's own announcement used instead.

**How the on-device judgement was made.** HumanityOS's own plan for a local model is
`docs/design/platform-architecture.md`, section "Local AI": a llama.cpp or Ollama subprocess on a
localhost API, "offline assistance, teaching, and NPC behavior", GPU when capable, CPU fallback. The
Outbox design (`docs/design/outbox-and-inbox.md`, section 5) also wants an AI helper that drafts and a
person who sends. While the game runs, the wgpu renderer owns most of the RTX 4070's 12 GB and the
frame budget, so a model for NPC dialogue during play has to be small enough to run on the CPU or in
a small slice of VRAM; only the 1.7B class does that on players' modest PCs. The 19B to 35B MoE
models are an operator-PC tier (helper, drafting, Library questions) used when the game is not
rendering, with part of the model held in system RAM.

## Notes on the candidates

### Spark-X2.6-1.7B (the small-tier brain)

- **Why it fits.** At 1.77 GB (Q4_K_M) it can run on the CPU beside the game, so it never touches the
  renderer's VRAM or frame budget, and it runs on players' modest PCs of any GPU vendor. It is in stock
  llama.cpp from build b10828, which matches the "Local AI" subprocess plan in
  `docs/design/platform-architecture.md` with no fork and no Python (`trust_remote_code` is only for
  the Transformers path, not the GGUF). The high/low reasoning switch suits NPC dialogue: the card
  says low effort cuts output length by 37.3% at a 4.0-point average score cost.
- **Limits.** Languages are tagged English and Chinese only, so it would not carry Spanish or Hindi
  NPC lines or help text well; benchmark scores are only in images on the card, so we could not
  read numbers. Whether 1.7B is enough for good NPC dialogue is unproven: a short rig test (a fixed
  set of NPC prompts, CPU time per reply measured beside a running game) would settle it.
- **For the legal finding.** Confirm the Apache 2.0 text and NOTICE in the repository files (the card
  states it; read the LICENSE file itself), the base model's own terms
  (`XHToken/Spark-X2.6-1.7B-Base`), any acceptable-use policy, and who SparkLLM is (the org page
  names a company, "SparkLLM", that offers a "proprietary Spark model family" alongside these open
  ones, so check the open line's terms are not tied to the proprietary one).

### Groot-19B-A3B-261023 (the operator-PC tier)

- **Why it fits.** Apache 2.0, a Q4_K_M GGUF of 11.7 GB, reads images as well as text, and its card
  reports beating its own base, Qwen3.6-35B-A3B, on 12 of 16 benchmarks with about 23% fewer output
  tokens. That makes it the strongest model in the group that comes close to the 4070: a private,
  on-device drafter for the Outbox AI helper (`docs/design/outbox-and-inbox.md`, section 5), a
  question-answerer over the Library, or a helper that reads a screenshot, when the game is not
  rendering.
- **Limits.** 11.7 GB of weights alone leaves no room on a 12 GB card for the context cache, so it
  needs a short context and some layers or experts in system RAM (the card gives no 12 GB guidance
  and recommends keeping at least 128K context "to preserve thinking capabilities"). Not for players'
  PCs. Languages not stated.
- **For the legal finding.** The publisher is anonymous ("The Groot Team", no company or people), so
  provenance and training-data terms need checking before anything depends on it. The 19B is
  "apache-2.0", but its sibling Groot-65B-A6B is "qwen-community-1.0", so confirm the 19B's base
  model terms (Qwen3.6-35B-A3B) really are Apache 2.0 from Qwen's own model card, not from Groot's
  or Clover's statement of them.

## Three-line summary

1. Best small-tier pick: **Spark-X2.6-1.7B** (Apache 2.0, 1.77 GB at 4 bits, stock llama.cpp), the only model here that can run local NPC dialogue or the in-app helper on the CPU beside the game on modest PCs, though only English and Chinese.
2. Best operator-PC pick: **Groot-19B-A3B** (Apache 2.0, 11.7 GB Q4_K_M, text and images), a private local drafter and Library helper, pending a legal finding that also settles its anonymous publisher and base-model terms.
3. Worth watching: **LFM3** is the best technical fit (16 languages, 1 GB, voice models) but its $10M revenue-threshold licence is not open source; Apex, Clover, Nanbeige and SenseNova-Loop are open but too big for 12 GB or not in llama.cpp yet; both news items are irrelevant to the project.
