# Ministral 3 3B Instruct: may the project serve its GGUF for speaking NPCs and the in-app helper

**Research date: 8 November 2026** (Pacific time). Every source below was read that day by an AI
research agent working for the project, identifying itself in every request as
"HumanityOS-research-agent/1.0 (automated AI research tool ...)". Hugging Face pages were read
through the public model API and raw file pages, arXiv and Mistral's sites as pages. Nothing was
downloaded, installed or run. Each source carries its own date where it shows one.

**I am not a lawyer, and this is not legal advice.** It is a reading of public licences, model cards
and policies, written so a later reader can check every word against the same sources.

Builds on the 2026-11-08 NPC brain and voice scan,
[`../research/2026-11-08-npc-brain-voice/README.md`](../research/2026-11-08-npc-brain-voice/README.md),
which recommended this model as the NPC brain for a modest PC and asked for this finding (Part 3,
"Dated legal findings still needed", item 1).

## The question

May HumanityOS serve Ministral 3 3B Instruct 2512 as a GGUF file from its own release downloads and
run it on the player's machine through llama.cpp for NPC dialogue and the in-app helper, and does any
base model, dataset, usage policy or other text add terms to its Apache 2.0 licence?

## Short answer

- **ALLOWED: redistributing the GGUF and running it for NPC lines and the helper.** Mistral states
  Apache 2.0 on the instruct, base and GGUF cards, in the launch post and in the paper's abstract
  (F1, F2). Apache 2.0 lets anyone reproduce and distribute the Work "in Source or Object form",
  and a GGUF conversion is Object form (F5).
- **The base model and its ancestors are Mistral's own, all Apache 2.0.** The listed base is
  `Ministral-3-3B-Base-2512`; the paper says every Ministral 3 model descends from Mistral Small 3.1
  (Apache 2.0) and that instruction tuning was distilled from Mistral Medium 3, Mistral's own model
  (F2). No outside model or dataset licence appears anywhere.
- **Mistral's Usage Policy does not apply.** Its scope sentence excludes "our open-source AI models
  and products" (F3).
- **One extra sentence sits under the licence**: "You must not use this model in a manner that
  infringes, misappropriates, or otherwise violates any third party’s rights, including
  intellectual property rights." It restates what the law already asks and is not part of the
  Apache text; nothing in NPC dialogue conflicts with it (F3).
- **NOT in the download: the vision encoder need not ship.** Mistral's own GGUF repository keeps it
  in a separate file (`...-BF16-mmproj.gguf`, 841,501,856 bytes); the text model alone is
  `Ministral-3-3B-Instruct-2512-Q4_K_M.gguf`, 2,147,023,008 bytes (F4).
- **No LICENSE file and no NOTICE file** in any of the three repositories, so the project ships the
  standard Apache 2.0 text itself (section 4(a)) and owes nothing under section 4(d) (F5).
- **UNCLEAR: what it was trained on.** The cards and the paper name no dataset (F6). That changes no
  licence term.
- **Recommendation: yes**, on the conditions under "What it means" below: Mistral's own Q4_K_M GGUF,
  text file only, the Apache 2.0 text and a credit beside it, the project's own system prompt (not
  the repository's, which tells the model it powers "Le Chat"), and an "AI" label wherever it speaks.

## Findings

### F1. The licence as stated

- **Instruct model card**, https://huggingface.co/mistralai/Ministral-3-3B-Instruct-2512 (repository
  created 2025-10-31, last modified 2026-07-15, not gated). Metadata `license: apache-2.0`,
  `base_model: mistralai/Ministral-3-3B-Base-2512`. Its "License" section, in full:
  > This model is licensed under the [Apache 2.0 License](https://www.apache.org/licenses/LICENSE-2.0.txt).

  > *You must not use this model in a manner that infringes, misappropriates, or otherwise violates any third party’s rights, including intellectual property rights.*

  (The asterisks are the card's own italics.) Its feature list adds:
  > Open-source license allowing usage and modification for both commercial and non-commercial purposes.
- **The launch post**, "Introducing Mistral 3", https://mistral.ai/news/mistral-3 (dated "December 2,
  2025"; its page data says modified 2026-10-08):
  > All models are released under the Apache 2.0 license.

  and of the Ministral 3 series:
  > Furthermore, for each model size, we release base, instruct, and reasoning variants to the community, each with image understanding capabilities, all under the Apache 2.0 license.
- **The paper**, "Ministral 3", arXiv:2601.08584, https://arxiv.org/abs/2601.08584 ("Submitted on
  13 Jan 2026"), abstract:
  > Each model comes with image understanding capabilities, all under the Apache 2.0 license.

### F2. The base model and the models behind it

- **Base model card**, https://huggingface.co/mistralai/Ministral-3-3B-Base-2512 (created 2025-10-31,
  last modified 2026-01-15, not gated): `license: apache-2.0`, **no** `base_model` of its own, and
  the same "License" section with the same italic sentence as F1.
- **The paper names the ancestry** (HTML version, https://arxiv.org/html/2601.08584v1):
  > all Ministral 3 models are descendants of Mistral Small 3.1

  > Pretraining of the Ministral 3 models starts from the Mistral Small 3.1 Base (MS3.1) model.

  For instruction tuning (section 3.2.1):
  > Unlike pretraining, each model is distilled from Mistral Medium 3 model

  and for images (section 2):
  > All Ministral 3 models use a 410M parameter ViT as a vision encoder for image understanding that is copied from Mistral Small 3.1 Base and kept frozen
- **Mistral Small 3.1 Base**, https://huggingface.co/mistralai/Mistral-Small-3.1-24B-Base-2503
  (created 2025-03-16, last modified 2025-07-28): metadata `license: apache-2.0`. Mistral Medium 3
  is Mistral's own model; Mistral is the licensor of the student either way, so distillation from it
  brings in no third party's terms.

### F3. The usage policy, the extra sentence, and the privacy notice

- **Mistral's Usage Policy**, https://legal.mistral.ai/terms/usage-policy ("Effective: June 11,
  2026"), section "Scope":
  > This Usage Policy does not apply to Mistral AI Products deployed on a customer’s infrastructure, on the infrastructure of our partners, or to our open-source AI models and products.
- **The italic sentence** quoted in F1 is printed under the licence on all three cards. It is not in
  the Apache 2.0 text and no gate asks anyone to accept it. Apache 2.0 already puts the risk of use
  on the user (section 7):
  > You are solely responsible for determining the appropriateness of using or redistributing the Work and assume any risks associated with Your exercise of permissions under this License.

  (Quoted with the file's line breaks joined.) The sentence states an obligation the law already
  imposes (respect others' rights). Judgement: it binds no one beyond the law, and the planned use
  does not touch it.
- **The cards' only other text of a legal kind** is `extra_gated_description`, pointing to Mistral's
  privacy policy for a gate. None of the three repositories is gated (`"gated": false` in the API),
  so nobody is asked to accept anything.
- Searched for and **not found** on the cards: an acceptable-use policy, prohibited uses, a claim over
  outputs, or a NOTICE.

### F4. The GGUF file, and what it contains

- **Mistral's own GGUF repository**, https://huggingface.co/mistralai/Ministral-3-3B-Instruct-2512-GGUF
  (created 2025-10-31, last modified 2026-01-15, not gated): `license: apache-2.0`,
  `base_model: mistralai/Ministral-3-3B-Instruct-2512`. Its card:
  > This model includes different quantization levels of the instruct post-trained version in

  (the sentence continues "**GGUF**, fine-tuned for instruction tasks"). Files and sizes (API tree):
  `Ministral-3-3B-Instruct-2512-Q4_K_M.gguf` 2,147,023,008 bytes; `-Q5_K_M` 2,474,178,720;
  `-Q8_0` 3,652,204,704; `-BF16` 6,866,745,504; `-BF16-mmproj.gguf` 841,501,856 (the vision
  projector and encoder, separate from the text model); `README.md`; `.gitattributes`.
- So the project can ship the text model without the vision encoder simply by not shipping the
  `mmproj` file. The card says the model has "3.4B Language Model" and "0.4B Vision Encoder".
- **The repository's default system prompt**, `SYSTEM_PROMPT.txt` in the instruct repository,
  begins:
  > You are Ministral-3-3B-Instruct-2512, a Large Language Model (LLM) created by Mistral AI, a French startup headquartered in Paris.
  > You power an AI assistant called Le Chat.

  It is an example file, not a term. An NPC or the helper running this prompt would claim to be
  Mistral's product.

### F5. What Apache 2.0 asks of a redistributor

From the licence text, https://www.apache.org/licenses/LICENSE-2.0.txt ("Version 2.0, January
2004"):
- Definitions:
  > "Object" form shall mean any form resulting from mechanical transformation or translation of a Source form, including but not limited to compiled object code, generated documentation, and conversions to other media types.

  (Quoted with the file's line breaks joined.) A GGUF file converted and quantized from the
  published weights is a conversion of this kind, so it is still the Work under the same licence.
- Section 4:
  > (a) You must give any other recipients of the Work or Derivative Works a copy of this License; and

  > (c) You must retain, in the Source form of any Derivative Works that You distribute, all copyright, patent, trademark, and attribution notices from the Source form of the Work, excluding those notices that do not pertain to any part of the Derivative Works; and

  Section 4(d) applies only "If the Work includes a "NOTICE" text file as part of its distribution".
- **No LICENSE and no NOTICE file** in the instruct repository (13 files, listed through the API), the
  base repository (14 files) or the GGUF repository (7 files). There is therefore no copyright line to
  retain and nothing owed under 4(d); 4(a) still asks the project to hand over the licence text.
- Section 6, on names:
  > This License does not grant permission to use the trade names, trademarks, service marks, or product names of the Licensor, except as required for reasonable and customary use in describing the origin of the Work and reproducing the content of the NOTICE file.

### F6. Training data: not disclosed

- No card carries a `datasets:` tag or names a dataset. The paper's HTML was searched for "corpus",
  "web data", "licensed data", "publicly available", "training data", "pretraining data" and "data
  mixture": it describes the training recipe (pruning and distillation from Mistral Small 3.1,
  between 1 and 3 trillion tokens) and an "SFT data mixture", but names no source. The default system
  prompt says "Your knowledge base was last updated on 2023-10-01."

## What is still unknown, and what would settle it

1. **What data trained Mistral Small 3.1 and Ministral 3.** Only Mistral can say; nothing public
   lists it. It changes no licence term. The industry-wide, unsettled question of whether a model's
   output can echo copyrighted training text applies as to any model; for short NPC lines the
   practical risk is low.
2. **Whether the italic sentence is meant as a condition of the licence.** Settled only by Mistral
   (a question through its support channel; free). Judgement: it makes no difference to a use that
   infringes no one.
3. **Whether 3B is good enough beside the game.** Not legal; the scan's rig test settles it.
4. **Whether the EU AI Act's Article 50 reaches the project**: left open in
   [`2026-11-06-social-platform-apis.md`](2026-11-06-social-platform-apis.md) (items EU-1 to EU-7); a
   lawyer's question.

## What it means for this project

### Certain

- The project may publish `Ministral-3-3B-Instruct-2512-Q4_K_M.gguf` as a release asset, or inside a
  release, and have the app fetch and run it, for NPC dialogue and the helper, provided each copy
  travels with the Apache 2.0 text (F5).
- No term read limits what the model may be used for, and nothing claims the text it writes (F1, F3).
  Players are bound by nothing from the model's side.
- Mistral's Usage Policy does not reach a downloaded open model (F3).
- Leaving out the `mmproj` file leaves out the vision encoder; nothing else need be removed (F4).

### Judgement calls

- **Serve Mistral's own GGUF, pinned by its file hash**, rather than a community conversion: the
  provenance is then the licensor's own (the LFS object id of the Q4_K_M file on the research date is
  `9ed150d4367e68df0ac8e1540f6ddc65b42d0ee26378329d1ecbca60f93fc5f8`). Serving it from the project's
  release assets rather than Hugging Face keeps a first-use download from telling a third party who
  is playing, as the Spark finding set out.
- **Write the project's own system prompt.** The repository's prompt makes the model say it powers
  "Le Chat" (F4). An NPC that claims to be a Mistral product is confusing and uses Mistral's product
  name beyond "describing the origin of the Work" (section 6).
- **Label it as AI wherever it speaks**, the helper especially. Not a licence term; see
  [`2026-11-08-spark-x2-6-small-model.md`](2026-11-08-spark-x2-6-small-model.md), F6.
- **What NPCs may say is the project's rule to write**, since the licence sets none.

### How the project would credit it

- **Beside the model file** (in the release asset's folder, or `data/ai/models/ministral-3-3b/` if it
  ever ships inside): `LICENSE` (the Apache 2.0 text from apache.org) and a short `README.md`:
  "Ministral 3 3B Instruct 2512 (Q4_K_M GGUF, text model only) by Mistral AI,
  https://huggingface.co/mistralai/Ministral-3-3B-Instruct-2512-GGUF, Apache License 2.0. Unmodified;
  the vision projector file is not included."
- **llama.cpp**, if bundled: its MIT text beside the runtime (per the Spark finding).
- **`data/credits.ron`**: a row with `attribution_required: true` (Apache 4(a) asks for the licence
  text, which a credit row points to) and `shown_in` naming "Credits" and the helper's settings; the
  same lines in `CREDITS.md` and `LICENSES.md`.
- **The download screen** names the model, its size (2.15 GB), its maker and its licence before the
  person agrees (the 2026-10-19 finding on showing each licence before an install).

### The question for the operator

**May Ministral 3 3B Instruct, Apache 2.0 with no outside terms but with undisclosed training data,
become the default NPC brain, served as Mistral's own text-only GGUF from the project's releases?**

Recommendation: **yes.** It is the cleanest licence of the candidates after Granite (F1 to F5), and
undisclosed training data is the norm for every non-OLMo model in the scan. Conditions: Mistral's
own Q4_K_M GGUF without the `mmproj` file, pinned by hash and served from the project's release
assets; the Apache 2.0 text and the credit beside it; the project's own system prompt; an "AI" label
wherever it speaks; and the rig test passed before it becomes the default.
