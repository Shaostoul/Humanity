# audio.cpp: its licence, its dependencies, keeping eSpeak NG out, and what a GGUF conversion does to a model's licence

**Research date: 8 November 2026** (Pacific time). Every source below was read that day by an AI
research agent working for the project, identifying itself in every request as
"HumanityOS-research-agent/1.0 (automated AI research tool ...)". The repository was read through
GitHub's command-line client and raw.githubusercontent.com. Nothing was downloaded beyond the text
files read, nothing was built, installed or run. Each source carries its own date where it shows one.

**I am not a lawyer, and this is not legal advice.** It is a reading of a public repository's
licence, build files and documentation, written so a later reader can check every word against the
same sources.

Builds on the 2026-11-08 NPC brain and voice scan,
[`../research/2026-11-08-npc-brain-voice/README.md`](../research/2026-11-08-npc-brain-voice/README.md)

## The question

May HumanityOS build audio.cpp into the desktop app (or ship its library beside it) to run Pocket TTS
on the player's machine, which licences come with it, how does eSpeak NG (GPL-3.0-or-later) stay out
of the build, and does converting a model to audio.cpp's GGUF format change that model's licence?

## Short answer

- **ALLOWED: audio.cpp itself, under Apache 2.0.** Its `LICENSE` opens "Copyright 2026 ShugoAI LLC /
  Licensed under the Apache License, Version 2.0" and then gives the full Apache text; there is no
  NOTICE file (F1).
- **Its vendored dependencies are all permissive**: ggml (MIT), SentencePiece (Apache 2.0, with
  Abseil Apache 2.0, darts-clone and protobuf-lite BSD-style, esaxx MIT-style), cJSON, cpp-httplib
  and libyaml (MIT), LZ4's library files only (BSD 2-clause), utf8proc (MIT plus the Unicode data
  licence). Each needs its notice reproduced in a binary distribution (F2).
- **eSpeak NG stays out of the default build**: the switch that compiles and links it is
  `AUDIOCPP_STATIC_ESPEAK`, default `OFF`, and its documentation says of that mode "eSpeak-ng retains
  GPL-3.0-or-later terms" (F3).
- **BUT the default build still carries a loader for an installed eSpeak NG.** audio.cpp's own
  adapter (Apache 2.0 code, compiled in every build) looks for `espeak-ng.dll` or `libespeak-ng.dll`
  on Windows and the usual library paths elsewhere, when a model that phonemizes with eSpeak runs.
  Pocket TTS does not: it reads text with SentencePiece. The FSF's view is that dynamic linking makes
  a combined work, so the clean path is to build only the Pocket TTS models (F3, F4).
- **A model's licence does not change when converted.** audio.cpp's own licence page: "a GGUF
  conversion keeps the license of the model it was converted from". Apache 2.0 counts "conversions
  to other media types" as the same Work, and CC BY 4.0 says a technical conversion "never produces
  Adapted Material" (F5).
- **Not part of a Pocket-TTS-only build**: one model folder in the source tree carries Liquid AI's
  non-OSI "LFM Open License v1.0" text, and several model folders carry their own notices; the
  `custom` model set leaves them out (F4).
- **UNCLEAR**: who ShugoAI LLC is (no location published), and whether the LFM licence file is meant
  to cover the code in its folder (F1, F4).
- **Recommendation: yes**, built with `AUDIOCPP_MODEL_SET=custom` and `AUDIOCPP_MODELS=pocket_tts`
  (plus `pocket_tts_small` if wanted), `AUDIOCPP_STATIC_ESPEAK=OFF` and the model manager off (both
  defaults), with the licence texts listed below shipped beside the binary.

### F3. How eSpeak NG stays out, and what the default build still contains

- **The build switch**, `CMakeLists.txt` line 148:
  > option(AUDIOCPP_STATIC_ESPEAK "Build and statically link GPL-3.0-or-later eSpeak-ng; keep data separate" OFF)
- **What turning it on does**, `docs/espeak_phonemizer.md`:
  > Alternatively, `AUDIOCPP_STATIC_ESPEAK=ON` builds the pinned eSpeak-ng 1.52.0 source and statically links its code into both CLI and server.

  and:
  > The license directory includes upstream COPYING, the original source archive, and our CMake integration/patch scripts. eSpeak-ng retains GPL-3.0-or-later terms.
  > Static builds are opt-in and distributors must meet the applicable requirements for the combined work, including corresponding source; copying only the license notice is not sufficient.

  (Quoted with the file's line breaks joined.)
- **What the default build contains anyway.** The same document:
  > `engine::audio::EspeakPhonemizer` is a reusable, optional runtime adapter for eSpeak-ng. SanoTTS (E2M and Piper frontends) and Inflect v2 use it.

  > By default users provide an installed shared library and its matching data.

  The adapter's sources, `src/framework/text/espeak_phonemizer.cpp` and `espeak_data.cpp`, are
  listed in the framework library (`CMakeLists.txt` lines 559 to 560), so every build compiles them.
  They are audio.cpp's own Apache 2.0 code (`espeak_data.cpp` packs and unpacks a data file; it
  contains no eSpeak data). On Windows the adapter calls `LoadLibraryW` on the names
  `"espeak-ng.dll", "libespeak-ng.dll"`; on macOS and Linux it tries the Homebrew and system library
  paths. It runs only when a model that uses eSpeak is loaded.
- **The Free Software Foundation's view of dynamic loading**, GNU's GPL FAQ,
  https://www.gnu.org/licenses/gpl-faq.html#GPLStaticVsDynamic (page stamp "$Date: 2026/01/13
  15:26:29 $"):
  > Linking a GPL covered work statically or dynamically with other modules is making a combined work based on the GPL covered work.

  (Quoted with the page's line breaks joined.) Whether a program that merely *can* load a library
  the user installed is distributing a combined work is disputed; the project does not need to find
  out, because Pocket TTS never calls the adapter (F4).

### F4. A Pocket-TTS-only build, and what it leaves out

- **Pocket TTS reads text without eSpeak.** `src/models/pocket_tts/text_conditioner.cpp` tokenizes
  with `tokenizers::tokenize_sentencepiece`; it includes no eSpeak header. The `pocket_tts` model
  target (`CMakeLists.txt` from line 1497) lists only `src/models/pocket_tts/` sources, and also
  registers Gradium's Phonon loader (`gradium_phonon.cpp`).
- **Choosing the models**, `CMakeLists.txt`:
  > set(AUDIOCPP_MODEL_SET "full" CACHE STRING "Model composite to build: full, core, or custom")

  > set(AUDIOCPP_MODELS "" CACHE STRING "Comma or semicolon separated model targets for AUDIOCPP_MODEL_SET=custom")

  The README shows the same option with `pocket_tts` among its examples
  (`-DAUDIOCPP_MODEL_SET=custom -DAUDIOCPP_MODELS=qwen3_tts,pocket_tts,qwen3_asr`).
- **What the full set would bring in.** `src/models/lfm_d1_omni/LICENSE.lfm1.0` is the "LFM Open
  License v1.0", whose licensor is "Liquid AI, Inc." (its definitions include "Commercial Use" and
  "Qualified Non-Profit Organization"; audio.cpp's own table says of the matching weights:
  "Commercial use is licensed only to organizations with less than USD 10M yearly revenue."). Nothing read says whether it
  covers the code in that folder (the source files carry no header, and neither the README nor
  `CMakeLists.txt` mentions the file); `src/community_models/nemotron_transcribe/` carries its own
  `LICENSE.apache-2.0` and `THIRD_PARTY_NOTICES.md`. A `custom` build with only `pocket_tts` compiles
  none of these.
- **Other defaults that keep the build small**: tests, examples and the C API are `OFF` by default
  (`ENGINE_BUILD_TESTS`, `ENGINE_BUILD_EXAMPLES`, `AUDIOCPP_BUILD_C_API`), as is the model manager.

### F5. Does converting a model change its licence?

- **audio.cpp's own statement**, `docs/model_licenses.md`:
  > audio.cpp is licensed under Apache-2.0. That license does not cover the model weights it loads: each model keeps the license of its original release, and a GGUF conversion keeps the license of the model it was converted from.

  (Line breaks joined.) Its table row for Pocket TTS (checked "2026-10-14"):
  > | `pocket_tts` | [kyutai/pocket-tts](https://huggingface.co/kyutai/pocket-tts), including [French](https://huggingface.co/kyutai/pocket-tts/tree/main/languages/french) | CC-BY-4.0 | Yes | Packaged language checkpoints, including the six-layer French model, share the upstream model-card license. Attribution required. | 2026-10-14 |

  The page also says "This page is a summary to help you find it, not legal advice."
- **Apache 2.0**, https://www.apache.org/licenses/LICENSE-2.0.txt:
  > "Object" form shall mean any form resulting from mechanical transformation or translation of a Source form, including but not limited to compiled object code, generated documentation, and conversions to other media types.

  (Line breaks joined.) A converted Apache 2.0 model is the same Work in Object form.
- **CC BY 4.0**, section 2(a)(4), https://creativecommons.org/licenses/by/4.0/legalcode.txt:
  > For purposes of this Public License, simply making modifications authorized by this Section 2(a)(4) never produces Adapted Material.

  (Line breaks joined.) A converted CC BY 4.0 model is still the Licensed Material, not an
  adaptation, and its attribution duties come along unchanged.

## What is still unknown, and what would settle it

1. **Who ShugoAI LLC is and where it is registered.** Settled by a state business registry search
   (free; which state is unknown) or by asking through the repository. It changes nothing in the
   Apache grant; it matters only for the project's habit of knowing its suppliers.
2. **Whether `LICENSE.lfm1.0` governs the code in `src/models/lfm_d1_omni/`.** Settled by asking the
   maintainer (an issue; free). Irrelevant to a Pocket-TTS-only build.
3. **Whether shipping a binary that contains an unused eSpeak loader counts as distributing a
   combined work with a library the user installs.** Contested; no court read. Avoided by never
   loading a model that calls the adapter, and if wanted removed entirely by a small patch to the
   build (an engineering choice, not a licence duty).

## What it means for this project

### Certain

- audio.cpp may be compiled into the desktop app or shipped as a library beside it, under Apache
  2.0, with its licence and the "Copyright 2026 ShugoAI LLC" notice (F1).
- Each vendored dependency's notice must travel with the binary (F2).
- With `AUDIOCPP_STATIC_ESPEAK=OFF` (the default), no eSpeak NG code or data is compiled in (F3).
- Converting Pocket TTS (or any model) to GGUF leaves its licence and its attribution duties as they
  were (F5).

### Judgement calls

- **Build only what is needed**: `AUDIOCPP_MODEL_SET=custom`, `AUDIOCPP_MODELS=pocket_tts` (and
  `pocket_tts_small` for the weakest PCs). That leaves out every model folder with its own licence
  questions, and every model that would call the eSpeak loader (F4).
- **Keep the eSpeak loader unreachable**: no eSpeak-using model is built, so it is never called. A
  later Piper, Kokoro or Kitten voice would bring the question back; the Paradee finding already set
  the rule that such voices need a non-eSpeak phonemizer.
- **Convert the models in the project's own pipeline** from Kyutai's pinned revisions, or check that
  any audio.cpp-converted package records its source revision, so the credits can name exactly what
  was converted.
- **Mind the project's no-caches rule**: the static eSpeak mode writes an extraction cache under
  `%LOCALAPPDATA%/audio.cpp/espeak-data/`. The recommended build never creates it. Any cache audio.cpp
  keeps across runs for Pocket TTS was not examined here and should be checked against the rule when
  the runtime is integrated (a product rule, not a licence term).

### How the project would credit it

- **Beside the runtime**: `LICENSE-audio.cpp` (the file as published, with its ShugoAI notice), and
  the licence texts of ggml, SentencePiece and its four third-party folders, cJSON, cpp-httplib,
  libyaml, LZ4 and utf8proc, in one third-party licences file (the one the 2026-09-06 attribution
  audit asked for, [`../attribution-audit-2026-09-06.md`](../attribution-audit-2026-09-06.md),
  finding 2).
- **`data/credits.ron`**, `CREDITS.md`, `LICENSES.md`: a row for audio.cpp ("audio.cpp by ShugoAI
  LLC, https://github.com/0xShug0/audio.cpp, Apache License 2.0") and for ggml.

### The question for the operator

**May audio.cpp (Apache 2.0) be the runtime that speaks Pocket TTS on players' machines, built with
only the Pocket TTS models and without eSpeak NG?**

Recommendation: **yes.** The licence and every dependency in a Pocket-TTS-only build are permissive,
eSpeak NG is out by default, and conversions keep each model's own licence (F1 to F5). Conditions:
build with `AUDIOCPP_MODEL_SET=custom` and `AUDIOCPP_MODELS=pocket_tts` (plus `pocket_tts_small` if
wanted), leave `AUDIOCPP_STATIC_ESPEAK` and the model manager off, ship the third-party licence file
described above, and pin the audio.cpp version (v0.9.4 or a later tag) so the build's contents are
known.
