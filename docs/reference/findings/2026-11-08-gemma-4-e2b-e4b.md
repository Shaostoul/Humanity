# Gemma 4 E2B and E4B: are they plain Apache 2.0 now, and does any Gemma term still apply

**Research date: 8 November 2026** (Pacific time). Every source below was read that day by an AI
research agent working for the project, identifying itself in every request as
"HumanityOS-research-agent/1.0 (automated AI research tool ...)". Hugging Face pages were read
through the public model API and raw file pages, Google's pages as pages. Nothing was downloaded,
installed or run. Each source carries its own date where it shows one.

**I am not a lawyer, and this is not legal advice.** It is a reading of public licences, terms and
model cards, written so a later reader can check every word against the same sources.

Builds on the 2026-11-08 NPC brain and voice scan,
[`../research/2026-11-08-npc-brain-voice/README.md`](../research/2026-11-08-npc-brain-voice/README.md),
which said Gemma 4 moved to plain Apache 2.0 in April 2026, recommended E4B for the in-app helper and
E2B for a rig test against the NPC brain, and asked for this finding (Part 3 (b), item 1).

## The question

Are Google's Gemma 4 E2B and E4B (instruction-tuned) released under plain Apache 2.0, so that
HumanityOS may serve them as GGUF files from its own release downloads and run them on the player's
machine, or do the Gemma Terms of Use or the Gemma Prohibited Use Policy still apply alongside?

## Short answer

- **CONFIRMED: Gemma 4 is plain Apache 2.0.** Both cards carry `license: apache-2.0` and link to
  Google's "Gemma 4 license" page, which serves the unaltered Apache License 2.0 text and nothing
  else ("Last updated 2026-04-01 UTC"). The launch post of 2 April 2026: "That's why Gemma 4 is
  released under a commercially permissive Apache 2.0 license." (F1, F2)
- **The Gemma Terms of Use no longer reach Gemma 4.** Their first line, as revised on 1 April 2026:
  "The terms below apply to Gemma models listed in the Appendix at bottom of this page. For Gemma 4
  terms, see the Gemma 4 license." The Appendix lists 24 entries (23 earlier releases, FunctionGemma
  twice) and no Gemma 4 (F3).
- **The Prohibited Use Policy does not attach either, as written.** It was last modified on 21
  February 2024, governs "Gemma or Model Derivatives" (terms the Terms of Use define by their
  Appendix), and is incorporated only by the Terms of Use. Neither Gemma 4 card mentions it, and the
  Apache text does not incorporate it. It still sits beside the Gemma 4 licence in the docs site's
  "Legal" menu, so a reader could assume it applies (F3, F4).
- **Nothing else binds**: no gate, no LICENSE or NOTICE file in the repositories, an "Intended use
  statement" that is advice, and "Guidelines ... for responsible use" on the card (F4, F5).
- **The text model can ship alone.** Google's own GGUF repositories keep the image and audio
  encoders in a separate `mmproj` file: E2B text model 3,349,516,256 bytes plus 986,833,664 for the
  encoders; E4B 5,154,941,280 plus 991,552,256 (F5).
- **UNCLEAR: the training data** ("web documents, code, images, audio, with a cutoff date of January
  2025", not itemized) (F6).
- **Recommendation: yes** for the helper (E4B) and for the rig test (E2B), on the conditions below.
  Keep the name "Gemma" to describing where the model came from (Apache 2.0, section 6).

## Findings

### F1. The cards

- **Gemma 4 E2B-it**, https://huggingface.co/google/gemma-4-E2B-it (repository created 2026-03-02,
  last modified 2026-11-03, not gated). Metadata:
  > license: apache-2.0
  > license_link: https://ai.google.dev/gemma/docs/gemma_4_license

  and `base_model: google/gemma-4-E2B`. Its header line:
  > <b>License</b>: <a href="https://ai.google.dev/gemma/docs/gemma_4_license" target="_blank">Apache 2.0</a> | <b>Authors</b>: <a href="https://deepmind.google/models/gemma/" target="_blank">Google DeepMind</a>
- **Gemma 4 E4B-it**, https://huggingface.co/google/gemma-4-E4B-it (created 2026-03-02, last modified
  2026-11-03, not gated): the same metadata with `base_model: google/gemma-4-E4B`; the two cards
  differ only in the model names (compared line by line).
- **Neither card mentions** the Gemma Terms of Use or the Prohibited Use Policy (searched for "terms",
  "prohibited", "policy" and "subject to"). For contrast, the card of an earlier model,
  `google/gemma-3-4b-it`, is gated and its raw text answered HTTP 401, so it was not compared.

### F3. The Gemma Terms of Use and the Prohibited Use Policy

- **Gemma Terms of Use**, https://ai.google.dev/gemma/terms ("Last modified: April 1, 2026"). Its
  first paragraph:
  > The terms below apply to Gemma models listed in the Appendix at bottom of this page. For Gemma 4 terms, see the <a href="/gemma/apache_2">Gemma 4 license</a>.

  Its definition of what it covers, section 1.1(c):
  > "Gemma" means the set of machine learning language models, trained model weights and parameters identified in the Appendix,

  (the definition continues "regardless of the source that you obtained it from"). The Appendix lists
  Gemma 1, Gemma 1.1, Gemma 2, Gemma 3, Gemma 3n, FunctionGemma, EmbeddingGemma, PaliGemma,
  PaliGemma 2, ShieldGemma, ShieldGemma 2, CodeGemma, CodeGemma 1.1, Gemma 2 JPN, DataGemma RIG,
  DataGemma RAG, RecurrentGemma, Gemma Scope, Gemma-APS, T5Gemma, VaultGemma, FunctionGemma (again),
  T5Gemma 2 and TranslateGemma. **No Gemma 4.**
- **How the Prohibited Use Policy attaches to those models**, Terms section 3.2:
  > for the restricted uses set forth in the Gemma Prohibited Use Policy at ai.google.dev/gemma/prohibited_use_policy ("Prohibited Use Policy"), which is hereby incorporated by reference into this Agreement; or

  (quoted with line breaks joined; the raw page writes the quotation marks as `&quot;`). The Terms
  also required redistributors to pass those use restrictions on "as an enforceable provision"
  (section 3.1); that duty belongs to the Terms and so does not reach Gemma 4.
- **The Prohibited Use Policy itself**, https://ai.google.dev/gemma/prohibited_use_policy:
  > Last modified: February 21, 2024

  ("Last updated 2024-08-05 UTC" in the page footer). It begins:
  > You may not use nor allow others to use Gemma or Model Derivatives to:

  It does not mention Gemma 4 or say that it applies to models outside the Terms.

### F4. Google texts that are not licence terms

- **The docs site's "Legal" menu** (on every page of ai.google.dev/gemma) lists, in order: "Terms of
  use", "Gemma 4 license", "Prohibited use", "Intended use statement". A menu is navigation, not an
  incorporation.
- **The Intended use statement**, https://ai.google.dev/gemma/intended_use_statement ("Last updated
  2026-04-01 UTC"):
  > Users are responsible for using and deploying Gemma and Gemma-based applications in a legal, responsible, and safe manner.

  (Quoted with the page's line breaks joined.) It names "Provide and adapt dialog applications for
  specific languages or cultures" among example uses. It grants nothing and forbids nothing.
- **The model card's "Misinformation and Misuse"** item:
  > Guidelines are provided for responsible use with the model, see the [Responsible Generative AI Toolkit](https://ai.google.dev/responsible).

### F5. The files: no LICENSE, no NOTICE, the encoders separable

- The E2B-it and E4B-it repositories each hold `.gitattributes`, `README.md`, `chat_template.jinja`,
  `config.json`, `generation_config.json`, `model.safetensors`, `processor_config.json`,
  `tokenizer.json` and `tokenizer_config.json` (API, research date): **no LICENSE and no NOTICE**.
  Apache 2.0's section 4(a) still asks for the licence text to go to recipients; 4(d) asks nothing.
- **Google's own GGUF repositories**, https://huggingface.co/google/gemma-4-E2B-it-qat-q4_0-gguf and
  https://huggingface.co/google/gemma-4-E4B-it-qat-q4_0-gguf (both created 2026-05-01, last modified
  2026-07-17, not gated, `license: apache-2.0` with the same `license_link`). Files and sizes:
  `gemma-4-E2B_q4_0-it.gguf` 3,349,516,256 bytes and `gemma-4-E2B-it-mmproj.gguf` 986,833,664;
  `gemma-4-E4B_q4_0-it.gguf` 5,154,941,280 and `gemma-4-E4B-it-mmproj.gguf` 991,552,256. The card
  describes them as:
  > * **GGUF** (Q4_0): Ready-to-deploy formats for broad ecosystem compatibility. Available for Gemma 4 E2B, E4B, 12B, 26B A4B, and 31B.
- **What the encoders are**: the card's table gives E2B and E4B each "Vision Encoder Parameters"
  "*~150M*" and "Audio Encoder Parameters" "*~300M*". In llama.cpp's layout the `mmproj` file carries
  the multimodal projector and encoders; not shipping it leaves a text-only model, all under the same
  licence.
- Apache 2.0 defines "Object" form to include "conversions to other media types", so a GGUF made by
  Google or by the project is the same Work under the same licence.

### F6. Training data

- The card, "Training Dataset":
  > Our pre-training dataset is a large-scale, diverse collection of data encompassing a wide range of domains and modalities, which includes web documents, code, images, audio, with a cutoff date of January 2025.

  It lists the kinds (web documents in "over 140 languages", code, mathematics, images) but no
  named dataset.

## What is still unknown, and what would settle it

1. **Whether Google regards the 2024 Prohibited Use Policy as covering Gemma 4.** Nothing read says
   so, and the Terms that incorporate it exclude Gemma 4 by their own first line (F3). Settled by
   Google saying so in writing (a question through the Gemma docs' feedback link; free). Judgement:
   as written, it does not apply; following it anyway costs the project nothing, since NPC dialogue
   and a helper are not among its prohibited uses.
2. **The training data.** Only Google can itemize it. It changes no licence term.
3. **Whether the EU AI Act's Article 50 reaches the project**: as in
   [`2026-11-06-social-platform-apis.md`](2026-11-06-social-platform-apis.md), a lawyer's question.

## What it means for this project

### Certain

- Gemma 4 E2B-it and E4B-it are under Apache 2.0 alone, as Google's own pages state (F1, F2). The
  project may publish their GGUF files as release assets, or inside a release, and run them for NPC
  dialogue and the helper, provided each copy travels with the Apache 2.0 text.
- The Gemma Terms of Use do not apply to Gemma 4, by their own words (F3). Their pass-through duty
  (section 3.1) therefore does not apply either: the project need not impose use restrictions on
  players.
- The image and audio encoders need not ship; the text model works without them (F5).

### Judgement calls

- **The Prohibited Use Policy does not bind Gemma 4 users**, because the only document that
  incorporates it excludes Gemma 4 (F3). Its content (no abuse, no harassment, no illegal content and
  so on) matches what the project's own safety rules already require of anything said on screen, so
  nothing changes in practice.
- **Use Google's own Q4_0 GGUF** (quantization-aware trained) for provenance, pinned by hash, rather
  than a community conversion; the scan's Q4_K_M sizes came from unsloth. Serve it from the project's
  release assets.
- **Ship the text model only**, unless a later feature needs images or voice input; the encoders add
  about 1 GB each and are not needed for spoken NPCs.
- **Say "Gemma" only to describe where the model came from** ("Gemma 4 E4B by Google DeepMind"), per
  Apache section 6; no Gemma logo.
- **Label it as AI wherever it speaks**, and write the project's own system prompt.

### How the project would credit it

- **Beside the model file**: `LICENSE` (the Apache 2.0 text, as served on Google's Gemma 4 license
  page) and a short `README.md`: "Gemma 4 E4B-it (Q4_0 GGUF, text model only) by Google DeepMind,
  https://huggingface.co/google/gemma-4-E4B-it-qat-q4_0-gguf, Apache License 2.0
  (https://ai.google.dev/gemma/docs/gemma_4_license). Unmodified; the mmproj file is not included."
  The same for E2B.
- **`data/credits.ron`**, `CREDITS.md` and `LICENSES.md`: one row and section per model.
- **The download screen**: name, size (5.15 GB for E4B, 3.35 GB for E2B), maker, licence, before the
  person agrees.

### The question for the operator

**May Gemma 4 E4B (and E2B for the rig test) be used under plain Apache 2.0, treating Google's 2024
Prohibited Use Policy as not attached to Gemma 4, which is what Google's own Terms page says?**

Recommendation: **yes.** Google's licence page, card metadata, launch post and Terms of Use all point
the same way (F1 to F3). Conditions: Google's own Q4_0 GGUF without the `mmproj` file unless image or
voice input is wanted, pinned by hash and served from the project's release assets; the Apache 2.0
text and credit beside it; "Gemma" used only to say where it came from; an "AI" label wherever it
speaks; and the rig test passed before E2B or E4B becomes a default.
