# 2026-08-15: the Market opens for real, and every node gets its own front door

Three releases today across two sessions sharing the checkout (this file covers
the orchestrator session; the film session shipped v0.1138.3 separately).

## v0.1140.0 + v0.1140.1: the Market's write side

PRIORITIES vision item 1. The offering/provider schemas already existed
(2026-08-12, unimplemented); the work was enforcement, not invention:

- `src/relay/core/market_payloads.rs`: faithful validators for provider_v1 and
  offering_v1 canonical-CBOR payloads, wired at the `put_signed_object`
  chokepoint so REST and federation gossip are both covered. Money firewall
  (settlement is directory-only; wallet/escrow modes and their reserved keys
  rejected), shop ownership (an offering must be signed by the key owning its
  referenced provider root), food-pantry rule, sim-prices-in-CR, future-clock
  cap.
- `scripts/import-offerings.mjs`: the bulk importer; merchant identity IS chat
  identity (same Dilithium3 derivation). Re-import updates by (provider, SKU)
  and refreshes TTL: the nightly-sync workflow the schema designed for.
- End-to-end proven against a throwaway relay; the first proof run caught the
  test relay running a pre-validator exe (the check that cannot fail, failing
  on purpose first).

## v0.1141.0: the Market's read side + need-shaped categories

- Native Market page now opens on a Directory tab (Classifieds remain second):
  `src/gui/pages/market_directory.rs` queries `GET /api/v2/objects`, decodes
  CBOR client-side, resolves latest revisions per (provider root,
  offering_key), filters TTL/expiry, splits Real/Sim by the payload's
  `reality`. Views: offering browse with search + category sidebar, provider
  storefronts, full detail with a copyable provider key (DM to arrange; the
  platform never moves money and the UI says so).
- `data/market/categories.json` rewritten need-shaped ({id, label, desc}:
  food, water, shelter, energy, health, care, clothing, tools, materials,
  repair, transport, growing, education, communication, services, emergency,
  other). One file now feeds the native loader, the web market selects and
  badge palette, and the relay validator (`shared_categories()` at the
  chokepoint, fail-open).
- Production ingest proven: a throwaway dev identity published the sample
  provider (Rivertown Bikes) + 2 offerings LIVE to united-humanity.us. First
  real rows in the public directory.
- Snapshot lesson repeated: the first market.png render showed "2 offerings"
  but an empty list; the seeds used 2023 timestamps and the TTL filter
  correctly hid them, and the headless render was spawning a real network
  fetch. Fresh `now_ms()` seeds + a `frozen` flag fixed both; the snapshot
  now proves the card layout.

## Per-node homepages (operator direction: "not everyone wants the same homepage")

- The seam: nginx's landing-page location prefers
  `/var/www/humanity-site/index.html` (a tree deploys never touch) over the
  repo default; `/site/` alias for custom assets; provisioner seeds the
  directory with a README. One file's presence IS the configuration.
- Flavors ship in `web/home/`. First flavor: `technical.html`, the
  engineer-facing intro (architecture, crypto spec table, federation,
  self-hosting, market-as-signed-objects). Subagent-drafted, then five
  load-bearing claims fact-checked against the code before deploy (/claim
  code, capability manifest keys, recovery shares, port, assets).
- DEPLOYED: public.guide serves the technical page; united-humanity.us keeps
  the mission-first page. Two front doors, one platform. The in-app flavor
  picker (Server Settings > Website) is logged as debt in
  `docs/design/in-app-ops.md`.

## White-label leftovers closed

- Native TURN now derives its credential-fetch base from the ACTIVE
  connection's ws URL (`WebrtcManager::start(my_key, relay_base)`); the dead
  `TURN_SERVER` const is gone. A self-hosted node's clients never call our
  production host.
- `data/gui/navigation.json` (consumed by nothing, stale for months) deleted
  with its embedded_data registrations.
