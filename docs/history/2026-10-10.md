## Lessons

- **"Letters and digits" is not one thing across languages.** The spec first said the web class
  `\p{L}`; Rust's `char::is_alphanumeric` is the Alphabetic property, which keeps combining marks
  such as a Devanagari vowel sign inside a word where `\p{L}` splits it. The shared cases now
  hold one that tells them apart (case 17), so the two clients cannot drift silently.
- **Test the guard on the way people actually copy the thing.** Backup screens number the
  recovery phrase, so people paste "1. word 2. word". The guard's "words in a row" saw a number
  between every pair and let the whole phrase through. Found by the desktop builder, fixed on
  both clients by leaving out number-only words, each test seen failing without the fix.
- **A legal duty can sit inside a feature's evidence path.** Sending a DM as evidence sends the
  key to any file it carries. The report-duties research turned a design detail into a hard
  rule: no file evidence, and no files or links shown to admins from a reported post.

- **A law can change between its passing and its start.** AB 1043's code page on the
  legislature's own site still showed the 2025 text; the version that takes effect on 1 January
  2027 is AB 1856's rewrite, signed a month earlier. A finding has to read the chaptered
  amendments, not only the code display.

- **Read the render, not just the build.** BUG-176 passed 3,529 tests. A snapshot fixture that
  compiles proves nothing; the PNG has to be opened and looked at before a GUI change ships.
- **Two builds of one spec still drift at the edges** (the damaged-identity rule went opposite
  ways); reading both reports side by side and choosing one rule for both caught it.

- **Let one client go first when the spec leaves words open.** For 10j the web built first and
  wrote its words into the spec; the desktop matched them and added a shared fixture so the two
  build the same bytes. That removed the round of "please match" messages the earlier steps
  needed.

- **Review before calling an arc done, not after.** The critics found in an afternoon what a week
  of red-first tests had not, because each test supplied its own world; and the one live break
  (BUG-180) came from a fake DOM that answered every lookup. A test page has to say "not there"
  the way a browser does.

- **A fix for one device can break the person's other device.** Holding a self-copy until the
  server answers was right for one device and wrong for two. Multi-device cases need their own
  scenario in the review, not just each client's own tests.
- **Review the fixes too.** The second review found six defects in the first review's fixes,
  among them that pacing had only made the original failure rarer. A fix that makes a failure
  rarer without making it impossible is a sign the protocol is missing a word (here, the
  server's answer to a send).
