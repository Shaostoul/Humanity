## Shipped

- **The server had been half-broken since 5 October (BUG-169).** A crawler (ShapBot) asked the
  git mirror for about a hundred half-gigabyte source archives, which Forgejo keeps on disk for a
  day; the VPS disk sat at 100% for about 22 hours. Fallout: both v0.1464.x deploys failed, the
  live relay ran from a DELETED binary (any restart would have left it down), the mirror stopped
  syncing (its queue kept the disk-full error), the disk guard posted its alert into
  #announcements 73 times, and the server's copies of the v0.1464.x downloads were cut short.
  Diagnosed read-only from directory change times. Fixed: the operator ran `just sync`; nginx
  now allows one archive request a minute for everyone (the crawler ignored Forgejo's built-in
  robots.txt); Forgejo deletes archives after 10 minutes and was restarted; the nine damaged
  release files were re-fetched and SHA-256 checked; `scripts/clear-build-cache.sh` keeps the
  relay binary when the build cache is cleared; the disk guard clears the archive cache, never
  deletes a build cache under a running build, restores a missing relay binary from backups,
  logs which folders are big, and alerts once per incident; the watchdog no longer posts
  "Relay recovered" after a single failed check (73 empty posts). v0.1464.2.
- **#announcements is one post per release.** 5,325 bot posts became 2,354, each named by its
  release title; the deploy workflow no longer posts, and the desktop build posts once, only
  after a successful build. A rerun of the cleanup turned 97 titles into "released" (it rewrote
  posts already rewritten); they were restored from the saved rows and the script fixed so a
  rerun is byte-identical. The re-seed archive matches the clean channel.
- **Web data sync answered strangers (BUG-170, v0.1464.3).** Anyone online could pull a web

## Lessons

- **A check that measures a neighbour of the question.** `just brief`'s VERSION row read "in
  sync" while the live relay ran a deleted v0.1463.0 binary. The disk guard's journal said
  "disk 100%" for a day without saying what filled it. Both now say more (the guard's WHERE
  line), and the playbook entry says where to look.
- **A rerun proof must compare content, not only counts.** The announcements script's second
  run deleted nothing and still rewrote 97 titles.
- **Parallel builds against one spec still need one owner of the protocol.** Writing the exact
  message names into the design before dispatching let three worktrees build server, desktop and
  web halves that merged without conflict; the one real hole (contact requests) was found by a
  builder and fixed in the spec, then sent to all three.
