## Learned

- Windows's MP4 reader does not apply an MP4's edit list the way the file means it (the fixture's
  first picture stamped 0.133 s, its sound 0.021 s, both 0 in the file), and tells the decoder's
  real output format only with the first sample. Both are written into `system.rs`.
- A program that names `mfplat.dll` in its import table does not start on a Windows "N" edition;
  the only safe way is loading at run time. Checked by looking for the ASCII DLL name in the built
  exe, with ole32 as the positive control.
- TaskStop on a background `just verify` leaves its test build running as an orphan (now in the
  tooling memory).
- Several red runs proved the test notes wrong rather than the code: the visible-area crop is never
  exercised by these fixtures (Windows reports the visible size and pads only the stride), and the
  late sound's red came from the declared starts reading as zero. Each note was corrected to what
  the run showed.
