## Learned

- A backup job that logs "pulled OK" can be failing for weeks: its only check
  (a valid SQLite header) was true of the stale file it kept fetching. The
  2026-09-29 health check recorded it as OK. A backup's proof is its age and
  its hash against the source, not its format.
- Deleting files can break the thing that manages them: a rotation line
  written as `ls glob | ...` under `set -euo pipefail` worked for as long as
  one file matched, and the cleanup that removed the last one stopped the
  script. Check what globs over a folder before emptying it.
- A test whose sender matches its own default can never fail the way real
  senders do: round one's smoothing test sent at exactly the rate the code
  assumed. Drive tests from the real sender at the rates real machines run.
- A rig must not measure the code under test with that code's own clock: a
  game clock running slow draws the figure slowly AND stamps the frames
  slowly, so speed on that clock still reads perfect. Check against a clock
  the code does not own.
- A screenshot can show nothing while every sample says the figure is there:
  a first-run window covered it on the rig's third run. Count the figure in
  the picture too.
- "No black texels" did not mean "not the palette": the bytes were dim
  colours in the wrong colour space, which an offline scan for black could
  never see. Check the decode path (sRGB vs linear), not just the values.
- A reviewer per fix keeps paying: three of the four fix lanes had a real
  problem the fixing agent did not see, and one fix (the name fallback) was
  wrong twice before it was right.
- Fixing one thing can arm another: making the Tasks page sign in would have
  made closing it sign the person out of voice and the game, because the
  relay treated one closed socket as the person leaving. The reviewer of the
  fix found it; a review after every parallel wave earns its cost.
