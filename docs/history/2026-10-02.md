## Learned

- A backup job that logs "pulled OK" can be failing for weeks: its only check
  (a valid SQLite header) was true of the stale file it kept fetching. The
  2026-09-29 health check recorded it as OK. A backup's proof is its age and
  its hash against the source, not its format.
- Deleting files can break the thing that manages them: a rotation line
  written as `ls glob | ...` under `set -euo pipefail` worked for as long as
  one file matched, and the cleanup that removed the last one stopped the
  script. Check what globs over a folder before emptying it.
- A test whose sender matches its own default can never fail the way real
  senders do: round one's smoothing test sent at exactly the rate the code
  assumed. Drive tests from the real sender at the rates real machines run.
- A rig must not measure the code under test with that code's own clock: a
  game clock running slow draws the figure slowly AND stamps the frames
  slowly, so speed on that clock still reads perfect. Check against a clock
  the code does not own.
- A screenshot can show nothing while every sample says the figure is there:
  a first-run window covered it on the rig's third run. Count the figure in
  the picture too.
- "No black texels" did not mean "not the palette": the bytes were dim
  colours in the wrong colour space, which an offline scan for black could
  never see. Check the decode path (sRGB vs linear), not just the values.
- A reviewer per fix keeps paying: three of the four fix lanes had a real
  problem the fixing agent did not see, and one fix (the name fallback) was
  wrong twice before it was right.
- Fixing one thing can arm another: making the Tasks page sign in would have
  made closing it sign the person out of voice and the game, because the
  relay treated one closed socket as the person leaving. The reviewer of the
  fix found it; a review after every parallel wave earns its cost.
- A red check has to fail for the reason the test names. The first draft of
  the "facing the wrong way" test handed the checker a field it does not
  read, so it failed on "no position" and stayed green when the fix was
  reverted. Reverting the fix showed it; the test now also asserts that the
  failure message is about the look.
- A capture that reports "ok" whatever it shows is not a check. probe-sweep
  now compares where the camera actually is against where it was sent.
- A red check does not need a revert: an older build of the same rig is the
  old behaviour. Pointing the 1b rig at the 1a archive gave the red the
  builder was refused. It also showed the freshness gate trusts file dates,
  which cannot say which tree a binary came from (BUG-133).
- An independent read of every source before a guide ships keeps paying:
  all fifteen load-bearing claims in the three new Library guides held, but
  the check found the diagnosis guide's only "is it dead?" step was trying
  the controls, which OSHA's electrical rule says is not enough (prove it
  with a tester), plus missing fuse, capacitor and carbon monoxide warnings.
  The claims were right; what was missing could have hurt a beginner.
- An OS prompt is an interruption the same way a focus steal is. Anything a
  dev tool starts that listens on every address costs the operator one click
  per new exe path, and dev work makes new paths all day. Count the rules the
  OS has piled up to see the real cost.
- A rig whose setup happens in a different order from a person's can never
  see a race that only the person's order has: the autopilot identifies after
  entering the world, so the "join before the ship exists" bug (1b round 4,
  HIGH) passed every rig. Make the rig take the player's order.
- Review rounds on a multiplayer feature keep paying long after the rigs go
  green: increment 1b passed every rig after round 1 and still had a HIGH
  in round 4. Stop when a round's findings fall to small edge cases, not when
  the rigs pass.
- A comment that says "this renders correctly" travels: the open cylinder's
  doc comment vouched for a pattern that only works when the rings run up,
  and the sphere, the hologram copy and the pin all copied it.
- A flake seen twice is a bug, not luck. The rig's exe copy failed with
  EBUSY on two different runs the same day, and both reruns passed, which
  made it easy to log as "timing" and move on. The cause was a fixed
  two-second retry against a lock whose length depends on how long the last
  game takes to let go of the GPU, and the same code sat in four rigs.
- Review the batch, not just the lanes: two seam reviews of one day's merges
  found 13 real defects that each lane's own tests could not see, three of
  them high or medium, because each lane was right on its own terms.
- A per-frame change that is small against its value is a rounding bug
  waiting for a fast monitor: test frame-sized steps at 60, 144 and 240 fps
  through the real tick, never a 600 s step (BUG-164 hid for ten weeks that
  way, as the tank level did before it).
