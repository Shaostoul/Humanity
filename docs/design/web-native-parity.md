# Web ⇄ Native Parity: rebuild plan

> **Status:** steps 1 to 6 done (2026-05-20 to 2026-10-22); what still differs is listed at the end, under "What still differs". Operator directive: the native app is the canonical/parent design; the web chat is the old/broken UI and must be rebuilt to mirror it. This is the systematic divergence map + migration order the rebuild executes against. **Incremental, component-by-component, the web chat stays usable throughout** (no big-bang rewrite).

## Approach

- **Native (egui) leads; web (HTML/CSS) mirrors.** Match native's structure + UX + layout. Web MAY render richer visuals where egui can't (emoji, gradients, video) but must NOT *diverge* in structure or behavior. egui's constraints define the shape; web fills it in faithfully.
- **Theme is already shared**, `web/shared/theme.css` is generated from `data/gui/theme.ron` (same tokens native reads). So colors/spacing/radii/fonts are already aligned; the divergence is **layout + component structure + which elements exist**, not palette.
- **Keep it working.** Migrate one component at a time behind the existing markup; never leave the web chat broken between increments.

## Migration order

1. **Left rail: tabs → stacked collapsible sections. ✅ ALREADY DONE (verified 2026-05-20).** The static `index.html` still has the tab markup, but `chat-ui.js::initUnifiedLeftSidebar` (called at runtime via `setTimeout(..., 0)`) rewrites it into stacked collapsible `.unified-section`s in native's order (DMs/Groups/Servers) with header counts + carets, and the CSS forces all panes visible in unified mode (`.sidebar-unified-left .sidebar-tab-content { display:block !important }`). The web left rail already matches native's structure. **Lesson: the static HTML misled the audit; the runtime DOM is the truth, always verify the rendered state, don't rebuild from the markup.**
   - **Studio relocation (1b), DONE v0.287.4.** The studio panel (`#stream-studio-panel`) was still in the left rail; native puts streaming on the right. `relocateStudioToRightRail()` (chat-ui.js) now moves it to the TOP of `#right-sidebar` at runtime (above the people list), preserving every control's id/handler. The full right-rail studio *widget redesign* (compact widget + modal + viewers) is Track S; this step just gets it onto the correct side.
   - **Scratchpad top row (1c), DONE v0.287.8.** Native's `draw_left_panel` renders a `# scratchpad` row at the very TOP of the left rail (above DMs/Groups/Servers) for a local-only workspace. Web already had the `__scratch__` channel (localStorage `hos_scratch_msgs`, `isScratchPad()`) but nested it INSIDE the Humanity server's channel list (vanished when collapsed). `initUnifiedLeftSidebar` now injects `#unified-scratch-row` as the first child of `#sidebar-unified-left` (click → `switchChannel('__scratch__')`, a one-time `switchChannel` wrapper keeps `.active` synced); the in-server copy was removed. `.unified-scratch-row` CSS (sidebar.css) styles it as a section-header peer with native's purple active accent.
   - **Identity header relocation (1d), DONE v0.287.9.** Native's left rail has NO persistent identity header (clean start, identity lives off the channel list). Web's `#my-identity` block (Profile link, public-key display, Share/Add contact card, Sync peers, Protect key, System info, My devices, sign-status) sat at the top of the left `#sidebar`. `relocateIdentityToMenu()` (chat-ui.js) now moves it at runtime into a header `#identity-menu` popover toggled by a 👤 `#account-toggle` button, same runtime-move approach as the studio (every control's id/handler preserved, idempotent, graceful). The web left rail now starts clean like native.
2. **Right rail align to native. ✅ DONE (v0.287.5 + v0.287.6).** Dropped the "People & Streams" overarching title (native has none). `renderUnifiedRightSidebar` now builds Friends + a full server-member list (count matches native; was de-duping → "(1)" vs native "(3)"); removed the right-rail Groups section (native keeps Groups left-rail only).
3. **Message rows + timestamp pill + inline reactions. ✅ DONE 2026-10-22** (the grouped rows and the bare pill came first, 3a and 3 of 2026-05-26). Native is `src/gui/widgets/row.rs` `message_row` and `src/gui/pages/chat.rs` `paint_timestamp_pill`, the `pill_expand` and `pill_ts_expand` Areas and the row's `context_menu`. On the web:
   - **The pill** (`web/chat/view/timestampPill.js`) holds the time (a `<time>` element), the Þ and the reactions INSIDE it, each its emoji and count, sorted, yours in the accent on a tinted ground (`reactionBadgesHTML`, which `chat-messages.js renderReactions` draws). The reactions were separate bordered pills beside it. The Þ is a real button.
   - **The expanded pill** (`web/chat/view/pillPopup.js`): hovering the Þ opens a bar at the pill's right edge, ↩ Reply, Pin, Edit, a Þ, the quick reactions and ∞ for all of them (`data/reactions.json` `top` and `all`), and the full time "YYYY-MM-DD HH:MM:SS UTC" left of the Þ. It stays while the pointer is on the pill or the bar. What the web adds: a click or tap opens it too; Enter or Space opens it with the focus on Reply, the arrow keys, Home and End move, Escape closes it and gives the focus back; it hangs off `<body>` so the list's edge never cuts it; where there is no room right of the pill (a phone) it opens under it, and the full time goes above the Þ instead of covering it. A private row (a P2P group, the scratch pad) offers Reply alone (BUG-178). Pin is offered to admins and moderators only, the people the relay lets pin; native offers it to everyone and the relay refuses the rest ("Only admins and mods can pin messages."), a native gap noted below. The old emoji strip (`showReactionPicker`, two copies) was removed.
   - **The message menu** (`web/chat/view/messageMenu.js`): a right-click, or the Menu key or Shift+F10 on the focused Þ, opens native's menu: Copy text, ↩ Quote / reply, Pin message, Pin for me (web only), Edit, Delete, then Report and Block on someone else's message. Each entry presses the row's own `.msg-actions` button, so it offers exactly what the row's rules allow. A right-click on a link, a picture, a player or a selection is left to the browser. With a mouse there is no hover action bar any more (native has none); a tap on a touch screen still shows it.
   - **The look:** sender groups alternate their ground, native's `bg_primary` then `row_stripe` (a new `--row-stripe` token, with a light value); names in the brightest ink at the body's size; rows flush, no hover ground; a solid ground under the list (the site's galaxy showed through the words); a reply's "↩ Name: words" line across the top of the row, muted; DM rows striped like a channel's (they had an accent bar and an orange wash).
   - **Fixed on the way:** a quote or list left an empty line under it (formatBody); a quote's bar, a list or a code block ran under the floated name and pill; code blocks are native's panel (card ground, as wide as the code, language and Copy always shown), and in the light theme their lines sat on pale boxes; a reaction showed for a moment and vanished (applied at once AND toggled back by the relay's copy, which goes to the sender too; now it waits for that copy, as native does); the site's hover hint covered the bar (`data-no-tip` in `shell.js`).
4. **Channel header + composer affordances. ✅ DONE 2026-10-22.** Header (native `draw_center_panel`): the darkest sidebar ground, "# general" at the heading size (`--text-xl`), then "|  description" small and muted (was "- description"); a DM's header is Back, "DM: Ada" in the DM ink, Report and Block; a group's is Back, its name in the group ink, "end-to-end encrypted" and Copy invite ticket (`--dm-accent`, `--group-accent`, new tokens from `theme.ron`). Composer (native input bar): one rounded box with the web's + first, then the text, Search, Pins with the count, ?, Attach (the word) and Send, the hint naming where the message goes ("Message #general", "Message Ada", "Message <group> (encrypted)"), the reply banner "↩ Replying to Ada: words". Wider than a phone, the pin bar over the messages and the header's search give way to the composer's buttons; on a phone they stay, so the text box keeps the room the phone check of 2026-10-12 gave it (191 px at 375 px wide, the hint on one line). A DM or a group clears the pin count.
5. **Top nav alignment. ✅ DONE 2026-10-22** (labels added v0.287.7). The "tiered nav" this step waited for no longer exists: native went back to one wrapping row in v0.196 ("The single row main menu is cleaner"), which is what the web's `shell.js` nav already is, with the same groups in the same order and the same category colours. Aligned: between groups a small dot, native's `separator_dot` (it was a 1 px line with no room around it), and Chat a group of its own before Watch and Files, as native groups it. Kept on purpose: the web's front-door icon first, Onboarding where native has Quests (Quests is in-game, native only), no Characters or Studio (native-only features).
6. **Sweep. ✅ DONE 2026-10-22.** `style.css` and `chat-voice.js` were already gone. Removed rules nothing draws: the old standalone voice rooms list (`.voice-room-item`, `.vr-name` and the rest), the category headers, `.dm-section`, `.dm-preview`, `.unified-stream-preview`, `.status-offline`, `.status-text-display`, the federation status dots, the delete-confirm and deleted-placeholder blocks, the profile `.bio-counter`, `.profile-field-row` and `.privacy-toggle`, `.message .time`, and the `--chat-speaking-ink` variable they used; and the dead `addMessageToChat` in `chat-social.js`. Spacing: the message list now runs nearly edge to edge as native's does (it had 18 px at the sides plus the rows' 10 px).

Each step is its own increment + its own version bump; the web chat is usable after every step.

## What still differs (checked 2026-10-22)

Compared at 1280 x 900 against the native snapshot `tests/snapshots/chat.png` (rendered 2026-09-27; `src/gui/widgets/row.rs` has not changed since; a fresh `just snapshot chat` was tried twice that day and the compiler ran out of memory both times, the machine at 1.5 GB free under other sessions' builds) and `tests/snapshots/nav_bar_wrapped.png`, and in a browser against a local relay, dark and light, at 1280 and 375 px wide. Screenshots of each step were kept with the work's report.

On purpose (the web is richer where the DOM allows, or the feature is web only):
- The avatar is the sender's identicon; native draws a coloured circle with their initial.
- A row shows the sender's role badge and the signature check (✓) after the name; native shows neither in the row.
- A date line between days and "N earlier messages"; native has neither (its pill's full time carries the date).
- Threads (a reply count under a message and the thread panel) are web only.
- The composer's + (command palette) is web only, and its bottom keeps room for the site footer's tab.
- Pin for me (a personal pin kept in this browser) is web only.
- On a touch screen a tap shows the row's action bar; native has no touch.

Still to do:
- A DM's rows have no Þ: native's DM rows open the expanded pill with Reply alone, and its menu offers Copy, Quote / reply, Report and Block. The web needs a reply that works in a DM before the Þ goes there.
- Native offers Pin to everyone in the expanded pill and the menu, and the relay refuses anyone but admins and moderators; native should offer it only where it works, as the web does.
- The full time beside the Þ is anchored left of it on both, so on a short name it covers the name and avatar; native lets it run into the left rail, the web keeps it inside the window.
- `docs/design/chat-layout.md` plans a single `view/chat-view.css` and engine/view split; the rows, pill, popup and menu are view modules now, the rails and modals are not.

## How to check

`node --test scripts/tests/chat-rows-web.test.js` (in `just rig-tests`) covers the pill, the reactions, the expanded pill (hover, click, keys, private rows, placement), the message menu, the rows the chat draws, formatBody's quotes, the header, the composer and the nav's dots. To look at the real thing, run a throwaway loopback relay (`scripts/lib/throwaway-relay.js` `startRelay`) and `node scripts/preview-server.js <port> --api http://127.0.0.1:<relay port>`, then open `/chat#joined` in two browser origins (127.0.0.1 and localhost) for two people.

## Guardrails

- **Don't regress working features.** The web chat has real, mature functionality (DMs, groups, voice/WebRTC, search, pins, reactions, profiles). Parity is about matching native's LOOK + STRUCTURE, not deleting capability. Anything web has that native lacks (voice, streaming) stays, native catches up separately.
- **Theme tokens only.** No hardcoded colors in the rebuilt CSS, use the `theme.css` vars (the web equivalent of native's theme-token rule).
- **Verify visually.** UI parity is judged by the operator on a real build (screenshots), like the prior server-settings styling work, ship incrementally so each step can be eyeballed.
